# Implementation Plan: Desktop-first GrabMeFood

**Branch**: `001-desktop-ui-redesign` | **Date**: 2026-11-10 | **Spec**: [spec.md](spec.md)

**Input**: Approved specification and clarifications in `spec.md`, approved root `DESIGN.md`.

**Execution authority**: The user now authorizes Plan → Tasks → Analyze → Implement →
verification without intermediate approval. FR-019 and the original Input describe the earlier
specification-only stage, not a permanent implementation ban. Business/API/data boundaries and
acceptance criteria remain unchanged. No commits, pushes, deployment, installations, or dependency changes.

## Summary

Apply the approved semantic palette and desktop-first composition to all 26 route definitions,
including fallback, preserving current data and working flows. Establish one shared responsive
application frame, reuse existing Radix-backed primitives, standardize dish/restaurant cards,
and repair local search/filter/navigation. Do not invent live location, accounts or review services.
Missing integrations become honestly unavailable, not successful simulations.

Implement in independently verified groups: foundations, discovery, cards/detail integrity,
secondary screens/unavailable states, accessibility and final audit. Preserve original records;
UI adapters may expose existing fields but must not fabricate relationships or merge conflicting
records by coincident numeric IDs. No new persistent data schema or external API.

## Technical Context

**Language/Version**: TypeScript ~5.7, React 18.3, existing Node runtime.

**Primary Dependencies**: Vite 6.3.5, Tailwind 4.1.12, React Router 7.13,
Radix UI, Lucide, next-themes already installed; no additions.

**Storage**: Existing static records and local component state. Theme preference may use
the existing next-themes package's local device preference; no account/data storage changes.
Search/filter/tab/sort state uses the existing route query string.

**Testing**: Existing Node test runner for pure TypeScript helpers, production Vite build,
TypeScript no-emit check, dependency-free source/route checks, available browser tooling only,
Impeccable audit/detector. Unavailable browser or human study checks are recorded, not inferred.

**Target Platform**: Web, keyboard and pointer, 320/390/768/1024/1440 CSS px, light/dark/system.

**Project Type**: Existing single React SPA, Figma Make wrapper retained.

**Performance Goals**: No synthetic waits or animation, image aspect ratios to avoid layout
shift; local search over existing records, no new requests. Record bundle warning baseline
rather than claiming performance metrics without measurement.

**Constraints**: Brand red #DC2626; existing semantic CSS variables and `.dark`; 44px minimum
standalone targets, 48px fields, WCAG AA text and non-text contrast; no destructive operations.

**Scale/Scope**: All 26 existing route definitions and relevant modals; no backend or migrations.

## Phase 0: Research

Read current scripts, source and dependency inventory; dispatch read-only research for
placeholder controls/ID collisions and available tooling. Record decisions and rejected
alternatives in `research.md`. Baseline: build passes (existing >500kB chunk warning),
8/8 insight tests pass. No dependency installation is needed for these checks.

## Phase 1: Design and Contracts

`data-model.md` describes adapters over unchanged records, URL criteria and UI states.
`contracts/ui.md` records route/interaction/identity/theme guarantees.
`quickstart.md` describes runnable verification without adding packages. The approved design
is applied, not re-opened through visual variants or a new world workshop.

## Delivery and Verification

Generate story-ordered tasks, then run read-only consistency analysis. Continue automatically
when gates pass; remediate within scope if a task is missing, without altering governance.
Each group must build and pass relevant tests before the next group. Browser checks, if
available without installation, cover routes, light/dark, widths, keyboard and filter recovery.
Do not mark a task done if its required verification is blocked. Human SC-001/SC-002 study
requires real participants and remains unverified until conducted; no simulated-user claims.
Run Impeccable audit, fix in-scope issues, and record evidence in `verification.md`.

## Complexity Tracking

No exceptions proposed. Broad source refactoring, a second UI/theme system, backend integration
and dependency upgrades are rejected. CSS migration must use semantic tokens and must not
hide layout overflow to create a false pass.
